# Canva 使用說明：資料、模型到分鐘候車

這份是 **2026-11-03 修訂版提示**。主講 22 頁約 23 分鐘，預留 2 分鐘問答；另附 2 頁備用。這次不報告增減班、營運成本或後段權重最佳化。

## 怎麼使用

桌面資料夾：`大稻埕_方法至分鐘候車_Canva素材_20261103`。

1. 把 `01_貼給Canva_方法到分鐘候車.txt` 貼進 Canva 的簡報生成工具。
2. 上傳 `版面參考_只沿用設計.pdf`，讓 Canva 延續既有米白／深灰／灰綠版面；這份 PDF 不作數據來源。
3. 從 `03_圖片依頁碼` 上傳下表的九張主圖。Canva 無法讀取電腦上的檔名路徑，因此在圖未上傳前先保留圖框。
4. 圖片放好後，檢查公式是否仍可編輯、圖片座標是否完整、左下文獻與講者備註是否存在。
5. 如果 Canva 一次不能處理全文，保留開頭的全域規則，分別生成第 1–11 頁、第 12–22 頁，再做兩張備用頁；每次都註明既有頁碼，避免它自行改寫數字。

本提示與圖片也保留在專案的 `docs/`、`result/presentation/method_to_minute_20261103/`。新圖只從既有 CSV 重繪，沒有重新訓練或重選模型。

## 數據口徑速查

- **模型資料：**21 場 × 四站 × 六時段＝504 列；不是 504 場獨立活動。九場北門、54 列作主要預測評分。
- **模型比較：**Ridge MAE 845.44、GAM 830.71、XGBoost 未加權 473.91、散場加權 440.28；四列是凍結模型的同口徑比較。
- **Lasso 補充：**隊友原縮放下，重新選參 Ridge 851.20、Lasso 848.52、OLS 846.33。全欄標準化 Lasso 846.37，與 OLS 幾乎相同，36/36 個編碼欄仍非零。這份分享缺原訓練程式；已核對輸出，未重現訓練。
- **Lasso 路徑：**圖中原縮放 r≈0.0316 的 MAE 824.55 是事後看九場的固定比例最低點，未由過去資料選到，不得當正式成績。選參後的合併 MAE 是 848.52。
- **最高時段：**2024/08/10 實際 11,101、模型約 8,359，少估約 2,742；這是同一個實際最高時段的事後評分。
- **候車第一版：**2024/08/10、每班假設剩餘 1,110 人、雙向各 50% 時，均勻／寬峰／集中峰約等 3.61／3.62／5.36 分。
- **空位敏感度：**九場集中峰在假設剩餘 25%／50%／75% 時，平均候車約 7.94／4.22／3.52 分。
- **不確定性：**九場各 1,000 次情境；合併情境平均候車中位數 2.90 分，5–95% 情境分位 2.68–8.12 分。這是模型假設下的模擬分布，未經現場資料校準。

## 報告口頭重點

第 14 頁可以說：「我們有實際比較 Lasso。它在原縮放下比同程序 Ridge 略好，但改善只有 2.68 人次；全欄標準化時幾乎等同 OLS，並未有效減少編碼欄。因此先保留作對照，主預測仍採目前九場表現較好的 XGBoost。這是本資料的結果，不是說 Lasso 理論上不好。」

第 18–21 頁可以說：「模型給的是一小時人數，但候車由乘客到達的分鐘形狀、列車時刻和空位共同決定。我們做三種分鐘到達情境，讓模型先顯示可能的等待差異；目前不能聲稱已測到真實分鐘到達。」

如果老師問「那下一步怎麼調度？」只答：「會把這個候車模擬接到班表與營運成本比較；那套權重、約束及結果留在下一次報告。」

## 重建圖片

在專案根目錄執行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/presentation/build_method_to_minute_assets.py
```

這個命令只讀既有結果、重繪四張圖、複製其餘圖並整理桌面素材；不訓練新模型、不重新調參。
