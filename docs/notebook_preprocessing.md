# propressing.ipynb 使用方式

本次將原有兩格北門加總程式擴充為可從頭執行的 19 格 notebook，清理與衍生表沿用現有 `src/` 函式，未改動底層計算規則。原 notebook 備份於 `.local/notebook_backups/propressing.before_preprocessing_20260929.ipynb`。

## 開啟與設定

1. 在專案根目錄執行 `uv sync --group notebook`。
2. 開啟 `notebooks/propressing.ipynb`，選本專案 `.venv/Scripts/python.exe` 作核心，或本次安裝於專案虛擬環境內的「北捷前處理 (.venv)」。
3. 從第一格往下執行。MySQL 需有既有 `codex-local` login path；notebook 不保存密碼。
4. `MONTHS=['202607','202608']` 預設只處理這兩月；改成 `None` 處理現有全部月檔。`STATION` 改觀察車站；`START_HOUR,END_HOUR` 控制總量區間，右界不包含。

## 流程

盤點 CSV → 型別／重複／非負人次檢查 → 月 Parquet → 日曆及 OD 配對覆蓋檢查 → 讀取 MySQL 事件 → 車站逐時與活動回歸表 → OD 流向表 → 總人次核對與輸出。

活動表保留取消及延期記錄；日期採本機資料庫，這次沒有重新查證活動公告。缺資料不補零，真實高值不刪除，同站進出保留。起訖站皆沿用來源標籤；時段的進／出閘分箱語意仍待查證，不能把來源時段的迄站加總直接稱為該小時實際出閘量。

## 分析前的限制

一場活動拆成多個車站／小時，不是增加獨立活動樣本。訓練與驗證按活動或年份切分。當場的實際狀態、尖峰和相對基準差值不可直接作為同場事前預測輸入；天氣及聲量也須限制為預測當時已知資訊。逐時數據不能提供真實的前 30 分鐘刷卡資料，較細時間粒度只能另做明確標示的模擬。
